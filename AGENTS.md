# AGENTS.md

## Назначение

Этот файл задает обязательные UI/UX-правила для всех AI-агентов и разработчиков, которые работают над интерфейсом проекта.

Цель: интерфейс должен выглядеть как современный SaaS-инструмент 2025-2026 года, а не как маркетинговый лендинг или экспериментальный concept UI.

Если возникает неоднозначность, выбирайте более строгий, плотный и функциональный вариант.

## Общий визуальный вектор

- Стиль: modern SaaS / internal tool / admin panel
- Характер: минималистичный, плотный, профессиональный
- Приоритет: ясность, скорость работы, читаемость, предсказуемость
- Анти-цель: playful, friendly, decorative, dribbble-style UI

Ориентир по ощущению интерфейса:

- `linear.app`
- современные B2B SaaS-панели
- внутренние рабочие инструменты

## Обязательные требования

### 1. Цветовая система

- Использовать только холодную палитру.
- База: `zinc` / `neutral` / холодные серые.
- Акцент: `blue` или `indigo`.
- Теплые тона запрещены.
- Нельзя использовать `orange`, `yellow`, `amber`, `beige`, теплые градиенты и любые “солнечные” акценты.

### 2. Компоненты

- Использовать только `shadcn/ui`.
- Не придумывать кастомные UI-примитивы, если у `shadcn/ui` уже есть эквивалент.
- Следовать стандартным composition patterns `shadcn/ui`.
- Для форм, диалогов, таблиц, вкладок, селектов, dropdown-меню, sheet, alert, skeleton и кнопок использовать готовые паттерны библиотеки.

### 3. Геометрия и формы

- Скругления должны быть минимальными.
- Разрешенные радиусы: в основном `rounded-sm` и `rounded-md`.
- Большие скругления не использовать.
- Кнопки в форме pill запрещены.
- Soft UI, glassmorphism и neumorphism запрещены.

### 4. Плотность и spacing

- Интерфейс должен быть компактным.
- Предпочитать плотность, а не воздух.
- Не раздувать вертикальные отступы.
- Избегать oversized hero-блоков, пустых зон и широких декоративных паддингов.

### 5. Типографика

- Использовать чистый sans-serif.
- Разрешено: системный стек или `Inter`.
- Декоративные шрифты запрещены.
- Типографика должна быть нейтральной, деловой и хорошо читаемой.

### 6. Тени и глубина

- Тени должны быть едва заметными или отсутствовать.
- Предпочитать границы вместо теней.
- Нельзя строить иерархию интерфейса на крупных тенях.

### 7. Границы и разделение

- У блоков должны быть видимые границы.
- Использовать `border`, `border-border`, `border-muted` и аналогичные токены темы.
- Разделение секций должно быть четким.
- Интерфейс не должен выглядеть как набор плавающих карточек.

### 8. Layout

- Использовать grid-based layout.
- Выравнивание должно быть строгим и ровным.
- Предпочитать панели, секции, таблицы, списки, формы и предсказуемые контейнеры.
- Нельзя строить интерфейс на случайных floating cards.

### 9. Интеракции

- Интерфейс должен ощущаться быстрым и функциональным.
- Разрешены только осмысленные transition-эффекты.
- Декоративные анимации запрещены.
- Любое движение должно помогать пониманию состояния, а не украшать экран.

## Явно запрещено

- Большие округлые карточки
- Pill-shaped buttons
- Яркие градиентные фоны
- Теплые цветовые палитры
- Glassmorphism
- Neumorphism
- Слишком большие кнопки
- “Dribbble-style” маркетинговый UI
- Декоративные hero-секции внутри продукта
- Визуальный шум ради “красоты”

## Практические правила реализации

### Предпочтительные паттерны

- Использовать `Card`, `Table`, `Tabs`, `Dialog`, `Sheet`, `Form`, `Input`, `Textarea`, `Select`, `DropdownMenu`, `Skeleton`, `Badge`, `Separator` из `shadcn/ui`.
- Предпочитать табличные и списочные представления вместо крупных карточек там, где важна плотность данных.
- Основные рабочие экраны строить как панели с явной структурой: sidebar, content area, secondary panels, toolbars.
- Для пустых состояний делать лаконичные блоки с коротким текстом и одной основной CTA.

### Предпочтительные Tailwind-ориентиры

- Скругления: `rounded-sm`, `rounded-md`
- Границы: `border`, `border-border`
- Тени: `shadow-none`, максимум `shadow-sm`
- Плотные отступы: `p-3`, `p-4`, `gap-2`, `gap-3`
- Акценты: `blue`, `indigo`, нейтральные серые

### Нежелательные Tailwind-решения

- `rounded-xl`, `rounded-2xl`, `rounded-full`
- `shadow-md`, `shadow-lg`, `shadow-xl` как основной прием
- Большие декоративные `p-6`, `p-8`, `p-10`, если они не оправданы задачей
- Градиенты, blur-эффекты и полупрозрачные стеклянные панели
- Перегруженные цветовые статусы без реальной необходимости

## Правило выбора при спорных решениях

Если есть два варианта UI:

- выбрать более компактный;
- выбрать более нейтральный;
- выбрать более структурный;
- выбрать тот, который ближе к internal tool / admin panel.

## Финальная проверка перед завершением UI-задачи

Перед сдачей любой UI-задачи агент должен проверить:

- Использованы ли только `shadcn/ui`-примитивы там, где они доступны.
- Осталась ли палитра холодной и нейтральной.
- Есть ли четкие границы между блоками.
- Не стал ли интерфейс слишком “воздушным”.
- Нет ли крупных скруглений.
- Нет ли декоративных градиентов и теплых акцентов.
- Не выглядит ли экран как маркетинговый лендинг вместо рабочего инструмента.

## Ключевой ориентир

Интерфейс должен выглядеть как серьезный современный SaaS-продукт: плотный, собранный, холодный, логичный и готовый к ежедневной работе.
